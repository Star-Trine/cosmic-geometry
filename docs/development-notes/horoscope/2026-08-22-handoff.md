  date: string;

## 4. 出生時刻不明

出生時刻不明はエラーではない。

正常な状態：

timeKnown: false
time: null

Partial Horoscopeとして処理する。

Partialでは：

- houses: null
- angles: null
- planet.house: null
- analysis.houseDistribution: null
- visualProfile.mode: "partial"
- visualProfile.houses: null

一方で、時刻に依存しないデータは利用する。

月については、出生時刻不明時にその日のサイン境界を跨ぐ可能性を調べ、
将来的に1候補 / 2候補として扱う設計。
この判定処理はまだ未実装。

## 5. Visual Profile 設計思想

Visual Profileは占星術的な人物解釈を生成するものではない。

InterpretationではなくVisualization。

「出生図にどのような構造的特徴があり、
それを視覚言語へ変換するとどのような形になるか」

を表現する。

基本三層：

2区分
→ Direction

3区分
→ Motion / Shape

4区分（Elements）
→ Color / Texture

その上に：

Planet
→ Light / Emphasis

House
→ Stage / 惑星が活動する空間

Aspect
→ Line / Relationship

Retrograde
→ Reverse / Special Motion

を重ねる。

---

## 6. Visual Profile 詳細

### 2区分

男性 / 女性区分の比率をそのまま方向性へ反映。

例：

masculine 7
feminine 3

↓

outward 0.7
inward 0.3

単純な二択ではなく比率として扱う。

### 3区分

各Modalityの性質をMotion / Shapeのアクセントとして使用。

Cardinal
→ 始動 / 放射 / 展開

Fixed
→ 安定 / 保持 / 密度

Mutable
→ 変形 / 流動 / 揺らぎ

### 4元素

Fire / Earth / Air / Waterを固定1色にはしない。

各元素を「色域」として定義する。

Element Distributionの割合から、その出生図固有のPaletteを生成する。

### 12 Signs

元素を親カラーとし、同じ元素に属する3サインを3区分によって差別化する構造を利用する。

例：

Fire
├ Aries        = Cardinal
├ Leo          = Fixed
└ Sagittarius  = Mutable

つまり、

Element
→ Color Family

Sign + Modality
→ Hue / Texture / Motion Variation

という階層を基本とする。

### Planet

惑星はVisual Profile上の主役。

惑星自体は一般的で分かりやすい惑星記号を使用する。

独自の強い惑星色を持たせるより、

Planet
↓
Sign
↓
Element / Sign Color
↓
その色を発光させるLight Source

という考え方を採用。

### House

単純なHouse DistributionだけでVisual Profileを決めるより、

「惑星＝役者」
「Sign＝役柄・性質」
「House＝舞台」

という構造を重視する。

その惑星が1〜12 Houseのどの舞台に存在しているかを、
Visual Profile上でどう見せるかを今後フロント側で検討する。

### Aspect

主要5アスペクト：

- Conjunction
- Sextile
- Square
- Trine
- Opposition

をそれぞれの幾何学的・占星術的イメージに沿った線表現へ変換する。

orbは線の強度へ変換。

現在backendでは：

strength = clamp(1 - orb / 5, 0, 1)

として0〜1へ正規化済み。

Reactではstrengthを、

- opacity
- width
- glow

などへ利用可能。

### Retrograde

基本案：

retrograde === true
→ 動きの方向を反転

具体的なアニメーション表現はReact側で決める。

## 7. VisualProfileData

backendで正式に生成済み。

type VisualProfileData = {
  mode: "full" | "partial";

  direction: {
    outward: number;
    inward: number;
  };

  motion: {
    cardinal: number;
    fixed: number;
    mutable: number;
  };

  palette: {
    fire: number;
    earth: number;
    air: number;
    water: number;
  };

  planets: PlanetVisualData[];
  houses: HouseVisualData[] | null;
  aspects: AspectVisualData[];
};

重要：

Node.jsは「描画そのもの」を生成しない。

Node.js
→ 視覚化に必要な意味のある数値・パラメータまで生成

React
→ そのパラメータをSVG / Canvas / CSS / Animation等へ変換して描画

という責務分離。

## 8. Visual Profileは2種類作る

Visual Profileについて、二つのUI案を両方採用する。

### A. 円形版

従来のNatal Chartの円形構造をベースに、
VisualProfileDataによる色・光・線・動きなどを重ねる。

### B. 抽象版

HoroscopeData / HoroscopeAnalysis / VisualProfileDataをもとに、
出生図の構造そのものをCosmic Geometry独自の抽象表現として可視化する。

両者は別々の出生データを作らない。

同一の：

HoroscopeData
HoroscopeAnalysis
VisualProfileData

を共有し、React側で異なるrendererとして表現する。
